# Agent オーケストレーション運用

複数エージェント（Claude Code / Codex / レビュアー Agent 等）を組み合わせて開発を進める上で、**実運用で痛い目を見たパターンを避けるためのルール**。役割表や個々の Agent 説明は [`agents.md`](./agents.md)、Plan / Review の保存形式は [`plan-review-workflow.md`](./plan-review-workflow.md) を参照。

ここで扱うのは「複数 Agent をどう同時に動かすか」「レビュー往復をどう収束させるか」「ブランチ滞留をどう防ぐか」という **オーケストレーション層** の取り決め。

## 1. レビュー収束ルール

### 指摘のトリアージ

レビュアー Agent（Codex / Claude `code-reviewer` 等）は、指摘を **2 段階** にラベル分けする:

- `[BLOCKER]` — セキュリティ脆弱性、ランタイムバグ、Plan の要件未達。これがある限り `NEEDS WORK` または `BLOCKED`。
- `[NICE-TO-HAVE]` — リファクタの提案、命名の好み、軽微なパフォーマンス改善、DRY 化。**これしか残っていなければ `APPROVE` を出す**。

`[NICE-TO-HAVE]` だけを理由に差し戻さない。残したい NICE-TO-HAVE は Plan の「残課題」または Review file の末尾に列挙し、後続タスクとして扱う。

### 往復の打ち切り

回数の固定上限は設けない。**BLOCKER がなくなった時点で APPROVE** が原則。ただし、レビュアーが BLOCKER を新規発見し続けて往復が収束しない場合は、笹木さん（または当該 PR のレビュー依頼元）に「ここで打ち切って実装/PR に進んでよいか」を **明示的に確認** する。打ち切る場合は残った指摘を Plan の `判断ログ` または「残課題」セクションに書き出し、後追いできる状態にする。

### スコープ制約（レビュアーへの前置き）

レビュアー Agent を起動するときは、依頼プロンプトに以下を必ず含める:

- **現行スタックは所与の前提**として受け入れる（Next.js 16 / React 19 / Postgres / `@waoon/ui` / Jotai 等）。代替ライブラリやフレームワーク変更の提案はしない。
- **Plan の Scope 外への大規模リファクタ提案はしない**。当該 PR で変更されていない既存コードの "bad practice" は指摘しない（必要なら別 Issue / 別 Plan に分ける）。
- Review file 末尾の verdict は `APPROVE` / `NEEDS WORK` / `BLOCKED` の **いずれか 1 つ** を明示する。これが次フェーズに進むかどうかの機械的な判定材料になる。

## 2. 並列稼働の制限

### 既定は直列

エージェントを複数同時に走らせて並列に PR を投げる運用は **既定では行わない**。1 タスク = 1 ブランチ = 1 PR を順に回す。

**Why:** 実運用で並列稼働させると、(a) 似たファイルへの同時編集でコンフリクトが多発し、(b) ブランチ切替が頻発した結果、未コミット変更が自動 stash されて「直したはずの修正がどこかに消える」事故が起きた。

### 並列を許す条件

並列稼働は、以下を **両方** 満たす場合のみ許可:

1. **明示的な許可**: 笹木さん / 当該タスクの依頼者が「並列で進めて」と明示している。
2. **スコープ宣言**: 並列稼働するエージェントごとに「触ってよいディレクトリ / パス」を事前に宣言し、**ファイルが絶対に競合しないことを確認する**。

例: 「Agent A は `apps/web/src/components/dashboard/` のみ」「Agent B は `packages/db/sql/` のみ」のように、ディレクトリ単位で完全分離できる場合に限る。`apps/web/src/lib/` のような共通ユーティリティを複数 Agent が同時に触ることは禁止。

### 探索系の例外

読み取り専用の `Explore` / `general-purpose` Agent による **調査・検索タスク** は副作用がないため、並列起動して構わない（むしろ推奨）。「ファイルを編集 / コミット / PR 作成する Agent」を並列にしないという制約として運用する。

## 3. ブランチ切替時の作業退避

ブランチ切替で未コミット変更を抱えているときの扱いは [`git-workflow.md`](./git-workflow.md#ブランチ切替時の作業退避) を参照。要約すると **裸の `git stash` 禁止**、`wip:` commit + Draft PR か `git worktree` を使う。

## 4. レビュアー Agent 起動時のプロンプトテンプレート

Codex / `code-reviewer` Agent を起動する際は、依頼文に以下のブロックを含めることで上記ルールを毎回適用する:

```text
レビュー方針:
- 指摘は [BLOCKER] / [NICE-TO-HAVE] にラベル分けすること。
- [BLOCKER] がなければ verdict は APPROVE。[NICE-TO-HAVE] のみで差し戻さない。
- 現行スタック（Next.js 16 / React 19 / Postgres / @waoon/ui / Jotai）は所与の前提。
  代替ライブラリやアーキテクチャ全面見直しは指摘しない。
- 当 PR で変更されていない既存コードの bad practice は指摘しない。
- Review file 末尾に verdict (APPROVE / NEEDS WORK / BLOCKED) を 1 行で明示すること。
```
