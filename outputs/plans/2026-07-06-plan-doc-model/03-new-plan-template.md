# Step 3: 新 Plan テンプレ（提案）

> [02-target](02-target.md) の原則を実物のテンプレに落とす。ここは**提案**で、本物の
> [`_template.md`](../_template.md) 改訂は Step 6（rules 反映）で行う。
> 設計判断: [thinking-log](../../../docs/thinking-log/2026-07-06-information-properties-and-placement.md)。

## 設計の要点（現行からの差分）

| 変更 | 現行 | 新 | 根拠（原則） |
|---|---|---|---|
| ヘッダの**状態欄を廃止** | ヘッダ「ステータス」＋末尾チェックリストで**二重** | 状態は**末尾チェックリスト1箇所のみ** | 状態機械は一次1つ（課題C 解消） |
| **定型ノイズを削除** | 担当 / git repo / slug / 更新日 | 削除 | 全 Plan 同一の情報量ゼロ |
| **PR/Review はリンクのみ** | 「関連 PR: TBD」「レビュー: …APPROVE」を手書き | リンク1本。verdict 文字列は書かない | 状態機械=リンクのみ・不変verdictはReview一次 |
| **現状コンテキストに凍結印** | 実装後に陳腐化 | 見出しに `（YYYY-MM-DD 時点）` | 陳腐化=凍結印 |
| **未確定事項は決着で移動** | 決着注記が判断ログと二重 | 未決のみ記載、決着したら判断ログへ**移動** | 二重記録の解消（課題C） |
| **残課題はリンク or 小節** | Plan と Review に列挙 | 追跡するなら Issue リンク | 状態機械=一次1つ |

## 新テンプレ本体（提案）

```markdown
# Plan: <タイトル>

| 項目 | 値 |
|---|---|
| 概要 | <ダッシュボード 1 行サマリ。README 生成の一次（Step 4 修正で追加）> |
| 前提 Plan | <あれば link / なければ「なし」> |
| PR | <作成後にリンク1本。未作成は空欄> |
| Review | <Review ファイルへのリンク。verdict は書かない> |

## 目的
<この作業で達成すること。1〜3 行>（不変）

## スコープ
### やること
### やらないこと（スコープ外）
（不変）

## 現状コンテキスト（YYYY-MM-DD 時点）
<関連ファイル・現状の実装・制約。リンクつき。日付時点のスナップショットとして凍結>

## 実装計画
<順序だてた手順>（不変・記録）

## 検証
<コマンド・手動確認手順。マージ後検証もここ>（不変・一次）

## リスク
<リスクと緩和策>（不変）

## 判断ログ
| 日付 | 判断 | 理由 |
|---|---|---|
（append-only の中核。未確定事項が決着したらここへ移動）

## 未確定事項（任意・未決のみ）
<まだ決まっていない問い。決着したら判断ログへ移動し、ここからは消す>

## 残課題（任意）
<後追い。追跡するなら GitHub Issue リンク>

## ステータス（状態のファイル側 唯一の置き場）
- [ ] 計画確定
- [ ] 実装完了
- [ ] レビュー完了 … → Review リンク
- [ ] PR 作成 … → PR リンク（以後の詳細状態は GitHub が正）
- [ ] マージ後検証
  - [ ] <環境ごとの確認項目>
```

## この設計での「状態はどこが正か」

- **計画中〜実装中（PR 前）**: ファイル末尾チェックリストが一次。
- **PR 作成後**: 詳細状態（open/merged/CI）は **GitHub が正**。ファイルは PR リンクを持つだけ。
- **README ダッシュボード**: この末尾チェックリスト＋PR 状態から要約（生成 or リンク集。Step 4）。

## 確認事項

1. **ヘッダから状態欄を消し、状態は末尾チェックリスト1箇所**に統一する方針でよいか
2. 削除する定型項目（担当 / git repo / slug / 更新日）はこれで過不足ないか
3. 「未確定事項は決着したら判断ログへ移動（両方に残さない）」を運用ルールにしてよいか
