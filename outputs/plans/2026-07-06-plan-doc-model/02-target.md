# Step 2: あるべき姿の原則（target）

> Step 1 の結論「不具合は〈状態機械 × 複製〉に集中」を受けて決めた設計原則。
> 分析軸は [index](index.md#背景の分析軸)。

## 背骨の原則（合意済み）

1. **不変な情報**（判断ログ・Goal・Scope・リスク・実装計画・verdict）
   → ファイルに一次で持ち、**要約複製は自由**（複製しても drift しない）。
2. **状態機械な情報**（フェーズ状態・PR 状態・指摘の解決・残課題・検証チェック）
   → **一次を1つに固定し、他所はリンクのみ（値を複製しない）**。
3. **陳腐化する情報**（現状コンテキスト）
   → 凍結印（日付）を打つか、生成源へのリンクに置換。

## 状態機械の一次: P3（フェーズで移動）＝合意済み

状態機械な情報の「1つの一次」は、**そのフェーズで実体を持つ媒体**に置く。
フェーズが進んだら一次が移動し、**移動元は値を捨ててリンクに置換する**（＝「移動の規律」）。

| 情報 | 計画中（PR 前）の一次 | 移行トリガ | 移行後の一次 | 移動元の扱い |
|---|---|---|---|---|
| フェーズ状態 | ① Plan / ③ README | PR 作成 | ⑥ GitHub（PR open/merged） | Plan/README は PR リンク＋状態を書かない |
| PR 状態（open/merged） | （まだ無い） | PR 作成 | ⑥ GitHub | — |
| PR 番号 | （まだ無い） | PR 作成 | ⑥ GitHub | 番号自体は生成後**不変**→ Plan に1回リンクを書けば OK |
| 指摘の解決状態 | ②Review（Claude 完結時） | GitHub でレビュー時 | ⑥ GitHub PR review | ファイルは「解決状態」を持たない |
| 残課題 / TODO | ① Plan | 追跡が要るなら | ⑥ GitHub Issue | Plan は Issue へのリンク |

### 例外: マージ後の検証チェック
「マージ後検証チェックリスト」は状態機械だが **GitHub に自然な置き場が無い**（stg 検証など）。
→ **Plan が記録媒体（一次）** のままにする。P3 とは矛盾しない（このフェーズで実体を持つ媒体＝ファイル）。

### なぜ P3 か（判断の要点）
「一次ソースは実際フェーズで移動している」（thinking-log D）。それを否定する GitHub 一元 / ファイル一元より、
移動を*認めて徹底*するほうが実態に合い、「Claude 完結時はファイルが一次」も自然に包含できる。

## README ダッシュボードの方向

手書き複製（＝ drift 源）をやめる。**GitHub から生成する / リンク集に縮小**のどちらか（詳細は Step 4）。
少なくとも「フェーズ状態・PR 番号を手書きしない」を確定。

## Plan 本体への含意（Step 3 の仕分けプレビュー）

| 現行セクション | 時間的性質 | あるべき扱い |
|---|---|---|
| 目的 / スコープ / リスク / 実装計画 | 不変 | **残す（一次・凍結）** |
| 判断ログ | 不変 | **残す（append-only の中核）** |
| マージ後検証チェック | 状態機械（例外） | **残す（Plan が一次）** |
| ヘッダ「ステータス」/ 末尾フェーズ | 状態機械 | **リンク化**（GitHub 参照。二重を1本に） |
| ヘッダ「関連 PR / ブランチ」 | 状態機械/不変(番号) | **リンク1本**（TBD 手書きをやめる） |
| ヘッダ「レビュー」 | 不変 | Review への**リンク**（verdict 文字列は複製しない） |
| 残課題 | 状態機械 | 追跡するなら Issue リンク、しないなら Plan 内に留める |
| 現状コンテキスト | 陳腐化 | **凍結印（日付）** を打つ |
| ヘッダ「担当 / git repo / slug」 | 定型ノイズ | **削除** |
| 未確定事項 | — | 決着したら**判断ログへ移動**（二重に残さない） |

## 確認事項

3. Plan 本体への含意（残す / リンク化 / 凍結印 / 削除）の仕分けで合っているか
