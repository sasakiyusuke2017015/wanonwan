# Step 5: 移行方針（既存 Plan の扱い）

> [03-new-plan-template](03-new-plan-template.md) / [04-review-and-readme](04-review-and-readme.md) を既存資産へどう適用するか。

## 決定: M2（全遡及）— ただし「ヘッダ正規化 + 凍結印」に範囲限定

全 12 Plan を新方式へそろえる（M2）。ただし**本文の全書き直しはしない**。
変更は機械的な範囲に限定し、不変な本文（目的 / スコープ / 判断ログ / リスク）はそのまま保つ:

1. **ヘッダ正規化**: 定型ノイズ（担当 / git repo / slug / 更新日）削除、状態欄削除、
   PR / Review はリンクのみ（verdict 文字列は消す）。
2. **状態は末尾チェックリスト1本**に集約（ヘッダとの二重を解消）。
3. **現状コンテキストに凍結印** `（YYYY-MM-DD 時点）` を付す。
4. **決着済みの未確定事項**があれば判断ログへ移動し、未確定事項側からは消す。

→ 「全書き直し」ではなく「全ヘッダ正規化」。一貫性を得つつ転記リスクを最小化。

## 対象

- 完了済み（✅）Plan・進行中 Plan・urgency-list-display を含む全 Plan。
- README は生成物へ切替（これ自体で全 Plan のフェーズ／PR の drift が一括解消）。

## 実行手順（Step 6 で実施）

1. `_template.md` を新テンプレへ改訂（[03](03-new-plan-template.md)）。
2. `reviews/_template.md` を新設（[04](04-review-and-readme.md)）。
3. 全 Plan のヘッダ正規化＋凍結印（上記 1–4）。**1 ファイルずつ検証**。
4. README 生成スクリプト作成 → README を生成物化（手編集禁止バナー）。
5. `plan-review-workflow.md` 反映（手書き→生成、テンプレ参照の修正、未確定事項移動ルール、
   `reviews/_template.md` 参照の実在化）。

## リスク

- **12 ファイルの機械編集で転記ミス**の恐れ → ヘッダのみの限定スコープ＋1 ファイルずつ検証で抑える。
- 完了済み Plan の書き換えは evergreen 的には不要（履歴は git log）。**一貫性優先**の判断として受け入れる
  （M3 との差はここ。全体の見た目の統一を取る）。
