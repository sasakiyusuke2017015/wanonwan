## 目的

コードレビューのループ（実装 → レビュー → 指摘）の**起動と検知を機械に移す**。
現状 `/pr-review` は人間が起動しており、レビュー忘れ・起動待ちが律速になっている。
PR に opt-in ラベルを付けるだけで、レビューコメントと verdict（マージ可否への接続）
まで自動で付く状態にする。

指摘 → 修正の反復（`@claude` メンションで修正 commit を積む Phase L2）は本 Plan の
スコープ外。まずレビューの自動化だけを小さく入れ、実績と quota 消費を実測する。

## スコープ

### やること

- `.github/workflows/pr-review.yml` の新設（`claude-code-action@v1`・サブスク認証）
- BLOCKER 検知の機械可読化: レビュー結果に応じて `review:blocked` ラベルを付け外しし、
  ゲート job がラベル有で fail する
- opt-in 運用: `ai-review` ラベルが付いた非 draft PR のみ対象
- リポジトリへのラベル 2 種（`ai-review` / `review:blocked`）の作成
- レビュープロンプトは [agent-orchestration.md §4](../../.claude/rules/agent-orchestration.md#4-レビュアー-agent-起動時のプロンプトテンプレート) のテンプレートを流用（日本語コメント）
- [agent-orchestration.md](../../.claude/rules/agent-orchestration.md) に CI レビューの節を追記
  （起動条件・override 手順・saved Review file との関係）

### やらないこと（スコープ外）

- **Phase L2**（`@claude` メンションによる修正 commit の自動化）。本 Plan の実績を
  2〜3 PR 見てから別 Plan
- **Phase L3**（レビュアーの回帰 eval）
- `outputs/reviews/` への saved Review file 生成の自動化。CI レビューはチャット内
  レビュー相当の扱いとし、saved Review が必要な作業は従来どおり `/pr-review` を使う
  （[plan-review-workflow.md](../../.claude/rules/plan-review-workflow.md) の保存基準は変えない）
- API キー（従量課金）への切り替え。quota が実際に痛くなってから判断
- develop / main への push トリガでの実行（PR のみ）

## 実装計画

1. **事前作業（笹木さん・手動）**: トークン発行と secret 登録、および
   **Claude GitHub App のインストール**。どちらもブラウザ操作のため Claude Code からは実行できない

   ```powershell
   claude setup-token          # 表示されたトークンをコピー
   gh secret set CLAUDE_CODE_OAUTH_TOKEN
   ```

   加えて https://github.com/apps/claude を対象リポジトリにインストールする。
   OAuth トークンはモデル利用の認証、App は action が PR にコメント・ラベル操作するための
   GitHub 側権限で、**両方必要**（App 未インストールだと review job が
   `App token exchange failed: 401` で落ちる。gate は fail-open しない）

2. **ラベル作成**（`gh label create`）: `ai-review`（opt-in スイッチ）/
   `review:blocked`（BLOCKER 検知結果。レビュアーが付け外しする）
3. **`.github/workflows/pr-review.yml` 新設**（`feature/pr-ai-review`）

   ```yaml
   on:
     pull_request:
       types: [opened, synchronize, ready_for_review, labeled, unlabeled]
   ```

   - **permissions**: `contents: read` / `pull-requests: write` / **`issues: write`**
     （ラベル操作は Issues API。無いと `review:blocked` 付与が 403 になり gate が
     fail-open する）/ `id-token: write`
   - **review job**: `ai-review` ラベル有 && 非 draft && **（event が labeled のときは
     付与ラベルが `ai-review` の場合のみ）** && event が unlabeled 以外のとき実行。
     ボット自身の `review:blocked` 付与は action の App トークンで行われ
     `GITHUB_TOKEN` の再発火抑止が効かないため、このガードが無いと labeled イベントで
     同じレビューが二重に走る（quota 2 倍・コメント重複）。
     `claude-code-action@v1` + `claude_code_oauth_token`。prompt は §4 テンプレート
     + 「BLOCKER があれば `gh pr edit --add-label review:blocked`、無ければ
     `--remove-label`」。`--allowedTools` は公式例の 4 種 + `Bash(gh pr edit:*)` に限定。
     model は quota 節約のため Sonnet を明示
   - **gate job**（review の後段 + labeled/unlabeled でも単独発火）: `ai-review` 有かつ
     `review:blocked` 有なら `exit 1`。`ai-review` 無なら skip（= opt-out で即グリーン）
   - concurrency で同一 PR の旧 run をキャンセル
4. **agent-orchestration.md に「CI 自動レビュー」節を追記**: 起動 = `ai-review` ラベル、
   human override = `ai-review` ラベルを外す（gate が skip になる）、
   `review:blocked` の手動剥がしは**しない**（review job が再付与して往復するため）
5. **実 PR で動作確認**（本 Plan の docs PR 自体に `ai-review` を付けて試す）

## 検証

> **実地検証のタイミング**: claude-code-action は PR 側の workflow 改ざんによる prompt
> injection を防ぐため、**workflow ファイルが default branch（= main）上の内容と一致する
> 場合のみ**実レビューを走らせる（不一致なら「skip + job は success」で終わる）。
> したがってレビュー本体の検証は、本 PR を develop → main までリリースした後、
> テスト PR で行う。それまでに検証できたもの: opt-in skip / gate pass / 認証
> （App + OAuth トークンのペアで 401 が解消）/ validation skip の挙動そのもの。

- `ai-review` を付けた PR に、push から数分で総評コメント + 行コメントが付く
- BLOCKER を含む変更（例: env フォールバック既定値の復活）を仕込んだテスト commit で
  `review:blocked` が付き、gate job が fail する
- BLOCKER を解消した commit で `review:blocked` が外れ、gate が pass する
- `ai-review` を外すと review / gate とも skip（既存 PR フローに影響ゼロ）
- draft PR では発火しない
- 1 レビューあたりの実行時間と、サブスク quota の体感消費を記録する（L2 判断の材料）

## リスク

| リスク | 対応 |
|---|---|
| **quota がローカル作業と共有**され、CI 消費で対話セッションが枯れる | opt-in ラベル運用で対象 PR を絞る + model を Sonnet に固定。痛くなったら `anthropic_api_key` への切り替えは secrets 参照 1 行の変更で済む |
| OAuth トークンの失効で CI が落ちる | 失効時の症状（認証エラー）と復旧手順（`claude setup-token` 再実行 → `gh secret set`）を workflow コメントに明記 |
| レビュアーの誤検知（false BLOCKER）でマージが不当に止まる | override = `ai-review` ラベルを外す（人間 1 操作で解除）。§4 テンプレートのスコープ制約（当該 PR 外の指摘禁止・スタック所与）で発生自体も抑える |
| fork PR からの secrets 露出 | 個人リポジトリで fork 運用なし。`pull_request` トリガは fork に secrets を渡さない GitHub 既定に依拠しつつ、前提が変わったら見直す |
| コード diff が Anthropic に送られる | 本 Plan の承認をもって組織判断とする（面談データは対象外。送信されるのはコードと PR メタデータのみ）。判断ログに記録 |
| PR 本文 / diff 経由の prompt injection でレビュアーに `review:blocked` を外させられる | allowed tools をコメント・ラベル操作に限定済みで、最終マージ承認は人間（笹木さん）。個人リポジトリで外部コントリビュータ不在のため現状は受容。コラボレータを追加する時点で見直す |

## 判断ログ

| 日付 | 判断 | 理由 |
|---|---|---|
| 2026-08-17 | 認証は API キーでなく**サブスク（`claude_code_oauth_token`）** | 追加コストゼロで開始でき、乗り換えは secrets 参照の変更だけ。quota 共有のリスクは opt-in 運用で抑える |
| 2026-08-17 | BLOCKER → CI 赤は**ラベル + ゲート job**で自作 | action に組み込みが無い。ラベルは人間にも見え、gate の判定材料としても機械可読。exit code をログから grep する案は脆いので不採用 |
| 2026-08-17 | 全 PR 自動でなく **opt-in ラベル**から始める | quota 消費の実測が無い状態で全 PR に付けると、サブスク枠の枯渇で対話作業ごと止まるリスクがある。実測後に既定 ON を再判断 |
| 2026-08-17 | human override は `review:blocked` でなく **`ai-review` を外す** | `review:blocked` を手で剥がしても次の synchronize で review job が再付与し、人間とボットの往復になる。opt-out 側を外せば review も gate も止まり一発で決着する |
| 2026-08-17 | 計画レビューの BLOCKER 1 件（labeled イベントでの自己再発火 → 二重レビュー）を反映し、review job に付与ラベル名のガードを追加 | ボットのラベル操作は App トークンのため `GITHUB_TOKEN` の再発火抑止が効かない。[計画レビュー](../reviews/2026-08-17-0405-pr-ai-review-review.md)参照 |
| 2026-08-17 | 事前作業に **Claude GitHub App のインストール**を追加（実装後に発覚した抜け） | OAuth トークンはモデル認証、App は GitHub 操作の権限で別物。App 未インストールだと `App token exchange failed: 401` で review job が落ちる（gate は fail-open しない） |
| 2026-08-17 | 実レビューの実地検証は **main へのリリース後**に行う | action の workflow validation が default branch（main）上の workflow との一致を要求する。PR 側の workflow 改ざんによる prompt injection 防止で、リスク表に挙げた injection 懸念の一部を action 自身が塞いでいる |
