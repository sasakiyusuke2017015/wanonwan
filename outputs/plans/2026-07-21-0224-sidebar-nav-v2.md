## 目的

左ペイン（サイドナビ）を、アプリ手書きの `<nav>`+`<button>` 実装から ui-catalog の新
`SidebarNav` へ乗せ替える。見た目・開閉は**笹木さん確定済み**の「展開（ラベル付き）⇄
アイコンレール（collapsed）」切替方式。非表示状態は廃止し、デスクトップでは常に
どちらかの幅で表示する。

## スコープ

### やる

1. **`sidebar-*` テーマトークンの定義と配線**（新部品は `bg-sidebar-primary` 等の
   Tailwind トークン依存だが**リポジトリに未定義**。未定義だとユーティリティ自体が
   生成されず全て無スタイルになる）。
   - **定義先は [apps/web/app/globals.css](../../apps/web/app/globals.css) の `@theme inline`**:
     `--color-sidebar` / `--color-sidebar-foreground` / `--color-sidebar-primary` /
     `--color-sidebar-accent` / `--color-sidebar-border` を `var(--sidebar-…)` 参照で登録。
     **注意: apps/web は Tailwind v4 の CSS-first 構成**（postcss は素の `@tailwindcss/postcss`、
     `@config` なし）。`tailwind.preset.ts` / `tailwind.config.ts` は v3 由来の遺物で
     app ビルドに読まれないため、そこに足しても効かない（計画レビュー BLOCKER 1）。
     vendored の tokens.css ではなく app 所有の globals.css に置くことで「部品・catalog
     無改修」の方針とも一貫する。
   - アプリ側は左ペインのコンテナ要素の `style` で `useTheme` の `colors` から
     `--sidebar-*` CSS 変数を注入（mount 後の保存テーマ切替にもそのまま追従する）。
     マッピング: `--sidebar` ← `primaryBgColor` / `--sidebar-foreground` ←
     `primaryContrastText` / `--sidebar-primary` ← `navActiveBgColor` /
     `--sidebar-accent` ← `navHoverBgColor` / `--sidebar-border` ← `primaryBorderColor`
     （実装時に見た目で微調整可。判断ログに確定値を記録）。
2. **[AppSideNav.tsx](../../apps/web/components/layout/AppSideNav.tsx) の置き換え**:
   - 手書き `<nav>` → `SidebarNav`（`groups` は単一グループ、`resolveIcon` → 既存 `Icon`）。
   - `linkComponent` に **GuardedLink**（新設の小さな client コンポーネント）を渡し、
     click を preventDefault → `guardedNavigate` に流して**未保存ガードを維持**する。
   - 位置決めは現行どおり `templates/SideNav`（fixed + topOffset）を使い、`isOpen` は
     常に true、**`width` を 56（レール）⇄ 208（展開）で切替**（scss の transition で
     幅アニメーション）。**レール幅は 36px から 56px へ拡大**: 新部品は ScrollArea の
     `px-2`（16px）+ collapsed item の `px-2`（16px）+ アイコン `w-5`（20px）で最小
     ~52px を要し、36px ではアイコンが clip される（計画レビュー BLOCKER 2）。
   - 現行のカスタム fixed ツールチップは削除（collapsed 時は SidebarNavItem の
     `title` 属性 = ネイティブツールチップに置換）。
3. **[AppLayout.tsx](../../apps/web/components/layout/AppLayout.tsx) の開閉モデル変更**:
   - `sideOpen`（表示/非表示）→ `collapsed`（展開/レール）へ。FloatingMenuButton は
     collapsed をトグル。
   - `sideShift` = `collapsed ? LEFT_PANE_WIDTH : LEFT_PANE_EXPANDED_WIDTH`（desktop）。
     `chromeShift` → SubHeader / Footer の `leftOffset`、main の左 padding は
     `md:pl-9` 固定クラスをやめ style で `chromeShift` に追従させる。
   - モバイル: 現行どおり左ペイン非表示 + 下部タブバー（変更なし）。
4. **定数**: ui-catalog [constants/app.ts](../../packages/ui/core/constants/app.ts) の
   `LAYOUT_SIZES` を `LEFT_PANE_WIDTH: 36 → 56`（collapsed レール幅として意味づけ直し）+
   `LEFT_PANE_EXPANDED_WIDTH: 208` 追加へ更新（未使用定数を残さない。evergreen）。
5. **[ui-catalog.versions.json](../../packages/ui/ui-catalog.versions.json)**: 未採番の
   `SidebarNav` / `SidebarNavItem` / `SidebarNavGroup` を 1.0.0 で登録。
6. ナビ定義（[navItems.ts](../../apps/web/components/layout/navItems.ts)）はそのまま
   単一ソースとして使い、`ResolvedNavItem` → `SidebarNavGroupModel` の変換は
   AppSideNav 内のアダプタで行う（roles ベースの出し分け・activeRole 連動は不変）。

### やらない（residual）

- **`templates/ShellLayout` へのシェル全面刷新**（flex ボディ方式で現行の
  fixed + `chromeShift` 方式と非互換。別 Plan）。
- モバイル下部タブの刷新・`NAV_ITEMS` の複数グループ化（現状 1 グループで十分）。
- 新 3 部品への stories / test の整備（上流由来。上流同期の別タスク）。
- 旧 `molecules/NavItem`（旧 1on1 用ダーク部品）の削除判断。

## 実装計画

### Phase 1 — トークン定義 + 定数

- apps/web/app/globals.css の `@theme inline` に `--color-sidebar-*` を登録（`var(--sidebar-*)` 参照）。
- `LAYOUT_SIZES` 更新（`LEFT_PANE_WIDTH: 56` / `LEFT_PANE_EXPANDED_WIDTH: 208`）。
- versions.json に SidebarNav 系 3 部品を 1.0.0 で登録。

### Phase 2 — AppSideNav 置き換え（apps/web）

- `GuardedLink` 新設（`href` + click → `guardedNavigate`。SidebarNavItem の
  `linkComponent` 契約 = anchor props 互換）。
- AppSideNav: `ResolvedNavItem[]` → 単一 `SidebarNavGroupModel` 変換、`activeHref` は
  `usePathname`（SidebarNav 内蔵の最長前方一致に委譲。`useNavigationItems` の
  `active` フラグは下部タブ用に残す）。コンテナに CSS 変数注入。`collapsed` props 化。
- カスタムツールチップ削除。

### Phase 3 — AppLayout 開閉モデル（apps/web）

- `sideOpen` → `collapsed`（**初期値: レール（collapsed=true）**。SSR/初回描画の
  `chromeShift` が 208 だとモバイル初回に大きな左寄せフラッシュが出るため、旧 36px
  レール同等の見た目で開始し、hydration フラッシュを従来水準に抑える）。
  FloatingMenuButton の open/close アイコンは展開/レールに合わせて維持。
- `sideShift` 2 値化、main の左 padding を style 化、SubHeader/Footer は既存の
  `leftOffset` 変数に乗るだけ（変更最小）。

### Phase 4 — 検証・仕上げ

- 不要になった旧実装（手書き nav・ツールチップ state）を残さず削除（evergreen）。

## リスク

| リスク | 影響 | 対策 |
|---|---|---|
| `sidebar-*` トークンの `@theme` 未登録・登録漏れ | ユーティリティ自体が生成されず全て無スタイル（背景 transparent・active 消失） | globals.css の `@theme inline` 登録を Phase 1 の最初に実施し、dev で色が付くことを確認してから Phase 2 へ。alpha 修飾（`/15`）は v4 が color-mix に展開するため hex 変数で機能する |
| GuardedLink の契約不一致（anchor props / ref） | 未保存ガードのすり抜け・遷移不能 | SidebarNavItem の `AnchorRest` 契約に合わせ、click 検証をブラウザ確認に含める |
| 幅 2 値化で chrome（SubHeader/Footer/main）とズレ | レイアウト崩れ | `chromeShift` 単一変数に集約されている構造を維持し、両状態で目視確認 |
| SideNav（入れ物）の `transition: all` が width 変化で暴れる | アニメ不自然 | 実機確認。問題あれば transition 対象を width に限定 |
| ベンダリング部品への改修が必要になった場合の上流乖離 | 次回上流同期のコンフリクト | 原則無改修（CSS 変数側で吸収）。やむを得ず触る場合は判断ログに記録 |
