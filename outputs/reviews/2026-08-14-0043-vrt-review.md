## 計画レビュー

- **目的とスコープ**: 「ダークを守る」ではなく「light 不変の担保」と定義できており、親 Plan の設計意図を正しく継いでいる。やらないこと（4-dark / Chromatic / E2E / addon-vitest 配線）も明確。
- **現状コンテキスト**: 全項目を実測している（Storybook 10.5.2 / stories 171 / app stories 0 / Playwright 未導入 / chromatic 残置 / `test:storybook` 未配線）。親 Plan の 2026-07-05 時点の数字との差分も判断ログに記録済みで、凍結日も付いている。
- **順序**: A（spike）を独立させ、storycap NG 時のフォールバックを用意している点は妥当。B の「2 回撮って差分 0」をゲートにする設計は flaky を先に潰す順序として正しい。
- **被覆範囲の判断**: 143 箇所が app 側にあり story 0 という実測に基づいて Playwright 導入を選んでおり、根拠がある。用途をスクリーンショット取得に限定してスコープ膨張を抑える方針も明記されている。
- **リスク**: storycap 非互換 / stg 依存 / Playwright スコープ / DB flaky / CI 時間 / dark 追加時の差分爆発を網羅している。HIGH の指摘は「リスクとして書かれていたが、実装計画側でその回避策が構造化されていなかった」点。
